# 使用看板需求规格

状态：`SPEC_APPROVED`。SQL 专项已确认；用户回复“spec 没问题”，Spec 总体审核通过，正文冻结。实施进度和验证结果分别见 [plan.md](./plan.md)、[verification.md](./verification.md)。

## 目标与范围

在现有 usage 页面中新增独立的“使用看板”，与现有统计功能同级。用户可以按日、周、月以及多个 API 密钥、多个分组查看总 tokens，图表和结果表使用一致的数据范围，能够区分真实零用量与缺失补零。

拟覆盖 `frontend` 和 `frontend2` 的用户用量页、管理员用量页，复用现有后端鉴权和共享请求层。该范围作为本次规格的待审核范围，不修改此前 frontend2 替换项目的冻结规格。

本次不包含计费规则调整、历史用量回填、使用记录清理、部署、Git 提交或推送。

## 已核实的现状

- 两套前端分别存在用户 `/usage`（frontend2 为 `/app/usage`，兼容 `/usage`）和管理员 `/admin/usage` 页面。
- 用户用量 API 根据登录身份隔离记录；管理员用量 API 可查询管理范围内的记录。管理员也可以进入个人用量入口。
- 使用记录存储于 `usage_logs`，具备 `user_id`、`api_key_id`、`account_id`、可空 `group_id`、`created_at` 及 tokens 计数。
- 现有使用记录筛选以单个 API 密钥、单个分组为主；现有用户趋势请求支持 `day/hour`，不能直接表达本需求的多选和 `day/week/month`。
- 现有总 tokens 口径为输入、输出、缓存创建、缓存读取四项之和。
- `frontend2` 在构建时复用 `frontend/src/api` 请求层；新接口应继续遵守此约定。

## 已明确的领域口径

**D-001：按 API Key 展示名称和用量，已由用户明确。**

图表和表格均按 API Key 统计，展示名称来自密钥名称，稳定身份使用密钥 ID。取消原始需求中的“平台 + 负责人”图例维度，删除负责人字段、负责人关联和平台分组要求。名称为空或关联密钥已不存在时回退为“API Key #ID”；同名密钥按 ID 区分，显示时仅在重名或缺失名称时补充 ID。

**D-002：普通用户只进入独立使用看板，已由用户追加确认。**

普通用户导航新增独立“使用看板”菜单，移除“使用记录”菜单；普通用户访问旧 `/usage`（新版兼容 `/app/usage`）也只渲染看板，不再渲染使用记录。管理员继续保留 `/admin/usage` 的使用记录和看板能力。该变化只影响前端导航和用户页面路由，不改变使用记录接口、管理员数据范围或 SQL。

## 目标行为

### FR-001 页面与权限

- 使用看板作为与现有统计同级的独立页内模块，具有清晰可见的“使用看板”入口和标题。
- 普通用户和管理员都能通过独立“使用看板”菜单访问看板，模块不增加角色隐藏或管理员专属开关；普通用户的旧 `/usage` 与新版 `/app/usage` 兼容地址只渲染看板，管理员 `/admin/usage` 仍提供使用记录和同名看板模块。
- 用户 usage 看板沿用个人记录范围，包括管理员从个人入口访问时；管理员用量页沿用管理数据范围。入口可见性不扩大普通用户的数据访问权限。
- 看板从上到下依次为查询条件区、图表区、结果表格区；时间粒度和时间范围放在查询区左上方。
- 看板筛选独立于现有统计和记录列表，切换模块时保留各自条件。沿用所在前端的布局、样式及可访问性惯例。
- 现有非角色性的全局运行模式限制沿用；看板本身不增加新的可见性限制。

### FR-002 日期与聚合

- 时间粒度使用集中枚举 `day/week/month`，显示为“日 / 周 / 月”，默认 `day`。初次打开默认为包含今天的最近七个自然日。
- 日、周模式使用开始日期和结束日期，格式为 `YYYY-MM-DD`；月模式使用开始月份和结束月份，格式为 `YYYY-MM`。
- 每次提交均检查日期真实有效且开始不晚于结束。输入不完整或无效时显示字段错误，不发送聚合请求，也不把旧结果标记为新条件结果。
- 使用浏览器报告的 IANA 时区，页面显示当前统计时区，浏览器无法提供时使用 UTC。后端使用同一时区确定边界。
- 日模式包含开始日期和结束日期的全天；月模式包含开始月份第一天到结束月份最后一天。后端采用左闭右开时间范围，避免遗漏结束日的秒和毫秒。
- 周固定按周一 00:00 至下一周周一 00:00 前聚合，标签显示周一至周日的日期范围。只纳入用户所选开始、结束日期以内的记录；边界周未选满时标记“部分日期”，不隐式扩大查询范围。
- 从日/周切换到月时取当前日期所在月份；从月切回日/周时采用当前月份范围的首日和末日。日与周之间切换保留日期；密钥和分组选择始终保留。
- 时间粒度和有效筛选条件改变后，重新请求并同时更新图表、表格；取消过期请求，旧响应不能覆盖新条件结果。

### FR-003 密钥与分组筛选

- API 密钥和分组均为可输入搜索的多选控件，输入用于查找并选择实际对象，不创建虚构对象或发送未识别名称。
- 空选择代表当前权限内不限该维度；同一维度多个选择按 OR，不同维度之间按 AND。
- API 密钥显示密钥名称，以 ID 去重和筛选；同名时附加 ID 区分，不展示完整密钥秘密值。分组同样使用稳定 ID。
- 分组筛选根据使用记录的 `group_id`，不能用密钥当前绑定分组替换历史记录的分组。
- 候选项搜索只更新候选项；选中、移除或清空条件后同步重新请求图表和表格。候选项应支持继续搜索/加载，不能静默只覆盖第一页。
- 普通用户的候选项和结果都限定于可访问范围；对明确指定的越权密钥拒绝访问，不静默扩大为全部数据。

### FR-004 tokens 与结果表

- 唯一用量事实来源为使用记录。允许关联密钥和分组获取名称；记录的用户 ID 只用于权限隔离。按所选条件纳入全部匹配记录，包括零 tokens、零费用记录，不额外套用现有统计中的 `actual_cost > 0` 条件，也不使用错误请求、账单余额或第三方用量替代使用记录。
- `total_tokens = input_tokens + output_tokens + cache_creation_tokens + cache_read_tokens`，跨记录求和。缓存细分计数不再次相加，图片计数和费用不换算为 tokens。
- 每行粒度为“时间段 × API 密钥”，展示“时间段”“API 密钥”“总 tokens 用量”；API 密钥列显示密钥展示名称。同一密钥的全部匹配记录合并计算。
- 默认全量聚合结果按 `total_tokens` 降序；点击该列头切为升序，再次点击切回降序。相同值按时间段开始时间、密钥 ID 稳定排序。
- 排序只影响表格顺序，不改变筛选范围、图表系列或图表时间轴。采用分页时必须先全量聚合及排序，再分页。
- 名称变更使用当前可读名称；身份使用 ID，避免同名对象合并。关联对象缺失时保留记录并显示带 ID 的占位名称。

### FR-005 图表

- 图表类型使用集中枚举 `line/bar`，默认折线图，两种类型互斥。
- X 轴为按时间升序排列的时间段，Y 轴为总 tokens。图表类型切换立即基于当前已加载数据重绘，不丢失筛选、排序或缺失状态。
- 每个系列按 API Key ID 唯一标识，图例显示密钥展示名称；不同 ID 的密钥分别显示，同名时附加 ID。图表不展示平台或负责人维度。
- 图表统计全部匹配记录，不受表格分页影响，也不默认为 Top N。任意时间段的所有系列之和应等于该时间段所有表格行之和。
- 密钥关联缺失时保留其记录并使用“API Key #ID”占位名称。名称采用当前密钥名称，不声称还原历史名称。

### FR-006 缺失补零

- 缺失状态使用枚举 `observed/missing`，不能通过 `total_tokens === 0` 判断。
- 图表和表格使用完全相同的 API Key 集合：范围内匹配记录出现的密钥，以及用户明确选择、且在权限内的密钥。每个密钥均补齐查询范围内全部时间段。
- 有至少一条记录时，状态为 `observed`，即使 tokens 合计等于 0。没有记录时，数值补为 0，状态为 `missing`。
- 表格真实零值显示普通 `0`；补零显示 `0` 并附灰色“无数据”标识。
- 折线图真实零值显示正常系列色的零点；补零显示灰色空心标识，涉及缺失点的连接段使用虚线，tooltip 明确写“无数据”。
- 柱状图真实零值保持柱高为 0，使用系列色基线标识提供可见和可交互目标；缺失值使用灰色占位标识，数值仍为 0，tooltip 写“无数据”。不得用非零高度伪造缺失用量。
- 整个范围没有使用记录时保留完整时间轴，并逐时间段显示灰色无数据占位。明确选择密钥时图表和表格逐密钥、逐时间段补零；未选择且无法识别密钥时，表格逐时间段显示“API 密钥 —、0、无数据”的全局占位行，不伪造真实密钥。
- 没有可识别密钥时，图表使用明确标为“无数据”的占位层，不虚构密钥系列。
- 请求失败不等于缺失，不执行补零；错误区提供重试，并保留当前查询条件。

## 拟新增的读取契约

以下为提议的新接口，当前仓库尚未提供，名称及契约在 Spec 审核通过后冻结。

- 用户看板：`GET /api/v1/usage/board`。
- 管理员看板：`GET /api/v1/admin/usage/board`。
- 查询参数：`granularity`、`start_date/end_date` 或 `start_month/end_month`、`timezone`、重复参数 `api_key_ids`、重复参数 `group_ids`、`sort_order`，以及表格 `page/page_size`。
- 客户端不提交用于放大数据范围的用户 ID。用户端身份取自登录会话；管理员端沿用管理鉴权。两者返回相同的业务结构。
- 响应包含规范化时间范围与时区、完整时间段列表、图表系列和点、当前页表格行及分页信息。系列和表格行携带 `api_key_id`、`api_key_name`；点和行携带 `total_tokens`、`record_count`、`data_state`，聚合计数使用 64 位整数。无密钥的全局占位项 `api_key_id` 为 null，不能与真实密钥合并。
- 单次响应的图表与表格来自同一匹配记录集合和一致的读取视图；表格翻页不得缩小图表结果。
- 数据源查询需覆盖完整结果，不能在浏览器遍历当前记录页后计算，也不能使用会截断维度的现有 Top N 趋势接口。
- 参数错误返回 400；未登录返回 401；越权返回 403；服务错误返回现有标准错误响应。无匹配记录为成功的空/补零结果。取消不显示失败消息，网络失败可按原条件显式重试。
- 读取操作幂等，不修改任何用量事实、用户、密钥或分组。旧用量接口与调用方保持兼容。

## SQL 审查边界

本次无需表结构、索引或数据迁移，新增读取使用记录的聚合查询。具体查询和可观察结果见 [SQL 专项审查](./sql-review.md)，已由用户确认，尚未执行。

SQL 专项核对以下内容：

- 事实归属、用户权限范围、历史 `group_id` 筛选，以及多选 OR/AND 语义。
- 时间半开区间、时区、周一周界、月界和边界周截取。
- 四项 tokens 求和、记录条数、稳定维度 ID，以及真实零值与缺失补零。
- 关联基数不放大计数，关联缺失或软删除不丢失历史事实；图表与全量表格可对账。
- 排序和分页发生在聚合之后，不使用 Top N 截断；读取一致性、参数化和查询取消。
- 无数据写入、无迁移执行；代码回退后旧接口行为保持不变。

独立 SQL 专项与 Spec 总体审核均已确认，可进入 Plan 阶段。
