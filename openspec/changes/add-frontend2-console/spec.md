# frontend2 全量替换技术规格（已冻结）

## 1. 目标行为

`frontend2` 必须成为 `frontend` 的功能等价替代品。等价指同一角色、同一后端状态和同一功能开关下，用户能找到并完成旧前端支持的全部任务，提交相同业务字段，获得语义一致的成功、失败和恢复反馈。

视觉、布局和步骤可以优化；字段、权限、业务状态、API 契约和可达能力不能减少。

## 2. 功能覆盖要求

### FR-001 路由与深链兼容

- 覆盖 `frontend/src/router/index.ts` 中全部现有业务路由、回调路由、动态路由和重定向。
- 新规范路径可使用 `/app/*`；所有旧用户路径必须提供 alias 或显式 redirect，并保留安全的 query/path 参数。
- OAuth、邮箱验证、支付、Key 用量查询、自定义页和法律文档深链不能经由旧前端兜底。

### FR-002 认证与会话

- 完整复现登录、注册、验证码、邮箱验证、找回/重置密码、token 刷新、退出和全部会话吊销。
- 完整复现现有 OAuth 提供商的发起、回调、账户创建/绑定、信息补全和失败恢复。
- 完整复现 TOTP、step-up 和 Passkey 能力；认证状态为 `unknown → authenticated | anonymous`，恢复完成前不得错误跳转或请求受保护数据。

### FR-003 普通用户功能

- 看板保留全部统计、时间范围、趋势、分布、近期记录和下钻。
- API Key 保留服务端搜索/筛选/分页、列配置、创建/编辑、自定义 Key、分组、状态、IP 白黑名单、额度、周期限额、到期、额度重置、复制、使用指引、导入和删除。
- 用量保留日期、Key、模型、分组、请求类型、计费类型/模式筛选，服务端排序/分页、列配置、统计、CSV 导出、错误请求列表和错误详情。
- 完整保留模型/可用渠道、渠道监控、批量图片、订阅、购买、充值、订单、兑换、联盟和个人安全能力。

### FR-004 管理员用户管理

- 服务端搜索、角色/状态/分组/API Key 分组/动态属性筛选，排序、分页、页大小和列显隐。
- 创建、编辑、启停、删除、批量修改并发/RPM、用户属性配置。
- 查看用户 API Key、允许分组、替换分组、充值、扣款、余额历史、平台额度及使用统计。
- 所有字段、确认策略、禁用条件和管理员保护规则与旧前端业务语义一致。

### FR-005 管理员资源与商业化

- 分组、渠道、账号、代理、订阅、支付计划、订单、兑换码、促销码和联盟管理必须逐项覆盖旧前端的读取和写入能力。
- 专用领域动作（OAuth 授权、账号测试/重认证、渠道监控、价格配置、批量编辑、导入导出、订单/计划状态流转等）使用专用交互，不得退化为统一状态切换。

### FR-006 管理员治理与设置

- 完整保留管理看板、运维、公告、备份/数据管理、系统设置、审计、管理用量、风控和提示词审计。
- 系统设置必须可编辑全部旧前端可编辑字段并保持分区、依赖校验、敏感字段策略和保存语义；只读摘要不算覆盖。

### FR-007 功能开关与自定义内容

- `simple mode`、`backend mode`、支付、联盟、渠道监控、批量图片、可用渠道及其他现有公开/管理设置必须驱动相同的菜单、路由和页面行为。
- 公告、自定义菜单、自定义页、品牌、Logo、文档链接和法律文档按现有配置展示。

### FR-008 模型与价格配置

- 用户端“模型与价格”必须完整展示现有 `/model-plaza` 返回的分组、模型标识、平台、渠道/分组定价、官方参考价、计费模式、价格区间、专属倍率、高峰倍率和可见性语义，不得丢弃已有字段。
- 管理端沿用现有渠道与分组配置作为定价规则的真值来源，完整支持已有 token、按次、图片、视频、缓存、区间和特殊媒体价格配置。
- 若新版页面所需的模型展示资料在现有契约和持久化结构中不存在，允许新增管理员 CRUD、持久化字段和 `/model-plaza` 只读响应字段；新增前必须在功能矩阵记录具体缺失字段与来源证据。
- 新增模型展示资料必须由管理员配置，用户端不得维护或硬编码；展示资料不能覆盖实际计费规则。
- 新增数据迁移必须提供默认值、旧数据兼容、回滚策略和契约测试，不得改变未配置时的现有计费结果。

## 3. 信息架构与导航

- 桌面采用混合导航：顶部只承载稳定的一级任务域，二级模块根据数量使用侧栏或页内标签。
- 一级域的最终名称由完整模块矩阵推导，不将业务不同的页面合并为一个通用页面。
- 所有二级和低频功能在最多两次导航操作内可达；当前页、父级域和返回路径始终可识别。
- 900px 以下使用抽屉/命令菜单承载完整导航；不能因折叠而移除入口。
- 旧路径访问后可进入新布局中的对应专用页面。

## 4. API 与数据契约

- 原样使用既有路径、HTTP 方法、字段名、稳定枚举值、分页和错误语义。
- `frontend/src/api/**` 是唯一共享请求层；`frontend2` 在构建期直接复用其公开导出，不复制客户端、不裁剪契约。对于旧认证页面已经直接通过共享 `apiClient` 调用、但 `auth.ts` 未提供公共函数的 OAuth 补全请求，允许 `frontend2` 以完全相同的方法、路径和字段调用共享 `apiClient`；该例外不得扩展到其他领域。
- API 依赖的共享类型、支付类型、业务常量、token 刷新、请求标记、URL 计算和错误归一逻辑一并复用。
- `frontend2/src/api/**` 只允许保留无业务语义的装配或兼容 re-export；不得创建独立请求客户端或与共享模块重复的请求函数。
- 页面可以建立纯展示 view model，但不能在 view model 中改变请求字段、状态或错误语义。
- FR-008 是唯一允许扩展现有后端契约的领域；扩展范围只限经矩阵证明缺失的模型展示或价格配置数据，并保持已有字段向后兼容。
- 有限业务状态、角色、模式和操作类型在 `frontend2` 中集中定义枚举，不新增业务布尔契约。
- 列表查询保留 AbortSignal、防抖和过期响应取消；写操作请求期间禁用重复提交。
- 401 只按既有刷新流程重试一次；403 不重试；409/422 映射字段错误；429 展示重试信息；网络/5xx 保留上下文并允许显式重试。

## 5. 权限与数据隔离

- 后端仍是最终权限边界；前端权限表同时驱动菜单、路由、按钮和预取。
- 普通用户不能看到、访问或预请求管理员能力；管理员切换到普通用户会话后不得残留管理数据。
- 用户 API 不拼接可篡改的用户 ID；管理员专用 API 沿用 `/admin/*`。
- simple/backend mode 与全部功能开关按旧前端语义执行，未知开关值采用旧前端相同的宽容或收紧策略。

## 6. UI、交互与状态

- 保留当前 `frontend2` 的年轻化设计方向，但数据密度、字段可见性和专业操作效率以业务页为准。
- 桌面表格支持稳定表头、服务端排序、分页、页大小、列配置和必要的批量选择；窄屏可使用卡片或横向表格，但字段和操作仍可访问。
- loading 使用结构匹配的 skeleton；empty 区分首次无数据与筛选无结果；error 提供原因和恢复动作。
- 表单提供字段级校验、服务端错误映射、未保存离开保护和提交中状态。
- 删除、扣款、禁用和不可逆状态变更需要上下文明确的确认；可恢复操作优先提供撤销或快速反向操作。
- 主任务点击数不得高于旧前端；高频查询条件可持久化，刷新和返回时保持合理上下文。

## 7. 响应式与可访问性

- 验收宽度：375、768、1024、1280、1440px；不得出现页面级非预期横向溢出。
- 所有交互具有键盘可达、可见 focus、可访问名称和正确语义；对比度满足 WCAG AA。
- 动画使用 transform/opacity，并遵循 `prefers-reduced-motion`。

## 8. 兼容与迁移

- 迁移期间不得修改 `frontend/**`；它只作为对照基线。
- 最终构建产物不得依赖旧 UI 页面、组件、样式或资源；允许在构建期消费唯一的共享 API/类型模块，产物运行时不依赖旧前端入口。
- 允许分模块交付到内部入口，但任何阶段都不得宣称“可替换”或切默认入口，除非 AC-001 至 AC-011 全部通过。

## 9. 验收条件

- **AC-001**：功能矩阵中全部旧路由和模块均为 `已通过`，无 `缺失`、`部分` 或旧前端兜底。
- **AC-002**：每个旧页面的字段、筛选、排序、分页、列配置、图表、详情、写操作、批量操作、导出、弹窗和跳转都有实现与验证证据。
- **AC-003**：普通用户和管理员的菜单、路由、请求与数据隔离回归通过；功能开关行为与旧前端一致。
- **AC-004**：登录、注册、OAuth、邮箱验证、密码重置、TOTP、Passkey、刷新和退出链路通过。
- **AC-005**：Key、用量/导出、用户管理、分组、渠道/账号、订阅购买、支付回调、订单、兑换和系统设置关键写链路通过。
- **AC-006**：旧 URL、书签、OAuth 回调、支付回调和动态页面深链全部由 `frontend2` 正确处理。
- **AC-007**：关键页面的 loading、empty、403、404、422、429、5xx、离线、取消和重试状态通过。
- **AC-008**：375/768/1024/1280/1440px、light/dark/system、键盘导航与 WCAG AA 检查通过。
- **AC-009**：`lint:check`、`typecheck`、单元/集成测试和生产构建通过；核心行为不得被 Mock 后仅验证组件存在。
- **AC-010**：`git diff -- frontend` 为空；`frontend2` 不创建重复请求客户端或重复 API 函数，旧认证页未公开封装的 OAuth 请求仅可通过共享 `apiClient` 按白名单原样复用；构建产物不依赖旧 UI，全量浏览器验收通过后才提交切流变更。
- **AC-011**：模型与价格首先完整消费现有数据；任何新增字段都有缺口证据、管理员配置入口、只读用户展示、迁移/回滚与契约测试，且未配置时计费结果不变。
