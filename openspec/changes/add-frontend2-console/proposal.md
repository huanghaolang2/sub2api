# frontend2 全量替换 frontend 提案（已冻结）

## 背景与问题

当前 `frontend2` 只覆盖少量核心页面，并将用户、分组、渠道和订单压缩为通用列表。该实现可以验证新视觉壳层，但无法替代 `frontend`。`frontend` 已承载完整的公开、认证、普通用户、管理员、支付回调、功能开关和自定义页面能力；任何只保留“核心页”的方案都会造成业务回退。

## 目标

在不修改现有 API、后端业务、数据结构和权限语义的前提下，使 `frontend2` 完整覆盖 `frontend` 的全部可见与可触发能力，并以新的 UI、信息架构和交互实现接管现有入口。

完成后必须满足：

1. `frontend2` 可以独立部署和运行；构建期直接复用现有 API、类型与必要常量，但不依赖旧 UI 的页面、组件、样式或资产。
2. 旧前端任一现有路由、字段、筛选、表格能力、图表、弹窗、跳转、导出、批量操作、状态变更和错误处理，在 `frontend2` 中均有等价入口。
3. 旧 URL、OAuth 回调、支付回调和外部深链继续可用；允许跳转到新的规范 URL，但不能落入 404 或旧前端。
4. 新布局允许将部分左侧导航改为顶部横向导航，但导航重排不得合并、隐藏或削弱业务能力。
5. 只有功能等价矩阵达到 100%，且权限和关键链路回归通过后，才允许切换默认入口。

## 唯一功能基线

- `frontend/src/router/index.ts`：路由、访问策略、回调和深链基线。
- `frontend/src/views/**`、`frontend/src/components/**`：页面字段、交互、状态和可访问入口基线。
- `frontend/src/api/**`：唯一 API 请求实现，包含路径、方法、参数、响应、token 刷新、请求头、错误和取消语义；`frontend2` 直接复用，不另写一套。
- `frontend/src/stores/**`、`frontend/src/utils/featureFlags.ts`：会话、公开设置、功能开关和跨页状态基线。
- `frontend/src/i18n/**`：现有语言和业务文案覆盖基线。

`frontend` 在迁移期间保持只读；最终产物不得依赖它，但验收必须逐项与它对照。

## 范围

### 公共与安装

- 初始化安装向导、首页、模型广场/定价、公开 Key 用量查询、法律文档、自定义页面和 404。
- 公告、品牌、公开设置、版本、主题、语言及由公开设置驱动的功能可见性。

### 认证与账户安全

- 登录、注册、邮箱验证、找回/重置密码、会话刷新和退出全部会话。
- GitHub、Google、LinuxDo、微信、钉钉和 OIDC 等现有 OAuth 入口、回调、补全、绑定和异常恢复。
- TOTP 登录与 step-up、Passkey、身份绑定/解绑、通知邮箱和账户安全设置。

### 普通用户域

- 看板、API Key、用量与错误请求、模型/可用渠道、渠道监控、批量图片。
- 订阅、购买、充值、订单、兑换码、联盟返利及全部支付方式和回调页。
- 个人资料、头像、密码、余额提醒、安全能力和自定义页面。

### 管理员资源与商业化域

- 管理看板、运维监控、用户、分组、渠道、账号、代理。
- 订阅、支付计划、订单、兑换码、促销码、联盟邀请/返利/转账。
- 各资源现有的查询、服务端筛选、分页、排序、列配置、详情、创建、编辑、复制、批量操作、导入导出、测试、状态切换和删除。

### 管理员治理域

- 公告、备份与数据管理、系统设置、审计日志、用量分析。
- 风险控制、提示词审计、渠道监控及现有专项配置弹窗。

### 全局质量

- 完整权限矩阵、simple/backend mode、所有功能开关、i18n、主题、响应式、键盘可访问性。
- loading、empty、403、404、409/422、429、5xx、离线、取消和重试反馈。
- 写操作防重复提交；危险操作确认；可安全撤销的操作优先提供撤销入口。

### 模型与价格的受限扩展授权

- 优先完整复用现有模型广场、渠道定价、分组覆盖价、官方参考价和倍率计算能力；不得因 `frontend2` 类型裁剪而误判为后端缺失。
- 只有功能矩阵证明现有契约或持久化结构无法承载新版“模型与价格”所需字段时，才允许在该领域新增后端字段、迁移和接口。
- 新增内容必须由管理员端配置并成为唯一数据来源；用户端与公开页只读取，不在页面代码中硬编码模型资料或业务价格。
- 模型展示资料与定价规则分离。展示资料不得建立第二套价格账本；现有计费解析仍是价格真值来源。

## 非目标

- 除“模型与价格的受限扩展授权”外，不修改 API 路径、HTTP 方法、请求/响应字段或错误语义。
- 除上述经证据确认的模型与价格字段外，不修改后端权限、数据库、迁移、计费、配额和业务状态机。
- 不新增团队、多租户、自定义角色或旧前端不存在的业务能力。
- 不以“页面更简洁”为理由删除字段、筛选、操作或状态。
- 本阶段不执行生产切流；切流属于全量验收通过后的独立发布动作。

## 实现原则

1. 先建立可追踪的功能等价矩阵，再按领域纵切实现，禁止用通用 CRUD 页面代替专用业务页。
2. 将既有 API 模块作为共享的深模块：保留原有导出接口和实现，`frontend` 与 `frontend2` 在迁移期共同消费；禁止在 `frontend2` 新建精简版 endpoint wrapper 或复制出第二套请求实现。
3. UI 采用“顶部一级任务域 + 页面内二级侧栏/标签”的混合导航；移动端折叠为可搜索的全量菜单。
4. 桌面数据页优先使用服务端筛选、排序和分页；本地过滤只用于已完整加载的小型静态集合。
5. 每个迁移模块同时补齐功能、权限、状态和回归测试，不能以构建成功代替功能验收。

## 回滚与切换

迁移期间两个构建产物并存。全量验收前仅提供内部入口；验收通过后再单独批准入口切换。由于不修改 API 和业务数据，回滚只需恢复旧静态入口，不涉及数据回滚。
