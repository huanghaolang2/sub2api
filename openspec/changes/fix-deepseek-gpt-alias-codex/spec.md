# DeepSeek 映射为 GPT 别名的 Codex 兼容修复

状态：`SPEC_APPROVED`，用户于 2026-10-22 明确审核通过，正文冻结。本文不涉及 SQL、数据迁移或新增持久化配置，跳过 SQL 专项审查。

## 背景与已确认需求

用户在目标 sub2api 后台配置 GPT 名称到真实 DeepSeek 模型的映射，例如 `gpt-6.1-sol` → `deepseek-v4.1-flash`；这些名称仅为验收示例，不硬编码为唯一支持的映射。故障发生在外部部署，不是当前本地运行的容器。

下游 Codex 继续使用原来的 GPT 别名、服务地址、API Key 和客户端配置。sub2api 已知实际映射目标，应负责提供正确的模型能力信息，并适配核心编程对话所用的请求和响应。

已在当前源码的实际目录补全入口复现两项不一致：

- 原生 Codex 目录只含 GPT 别名时，缺失字段按 GPT 别名补全，得到 `low/medium/high/xhigh/max/ultra`，没有使用映射后的 DeepSeek 能力默认值。
- 原生目录中 GPT 别名带有 `use_responses_lite=true` 时，映射目标改为 DeepSeek 后，该字段仍可保留。

现有 DeepSeek 工具转换和模型目录相关测试通过，但未覆盖以上组合。临时诊断测试失败可证明目录行为，不代表已经复现外部部署原始 request ID 的完整故障。

## 目标与范围

G1. 保留公开 GPT 别名，下游不需要修改配置；以实际映射目标决定 DeepSeek 能力和请求兼容规则。

G2. 支持核心 Codex 编程链路：文本与流式输出、客户端函数/自定义工具调用、工具结果回传、连续对话。

G3. 修复覆盖本地生成目录、上游目录补全，以及现有 HTTP/SSE 和已启用的 WebSocket → HTTP Bridge 转发路径；同一映射的目录与执行行为保持一致。

G4. 复用现有模型映射、能力快照、工具转换和会话恢复设施；不新增管理端配置或数据库字段。

不在范围内：识别上游网站内部未披露的模型替换；模拟 DeepSeek 不提供的 GPT 云端工具或私有协议；解密其他供应商生成的历史推理内容；扩大现有 WebSocket 入口开放范围；重构其他供应商；修改计费规则；自动部署、提交或推送。

## 行为与契约

### R1. 模型身份和适配边界

- 公开名称由已有映射决定。客户端模型目录的 `slug`、请求模型和返回给客户端的响应模型继续使用公开别名。
- 上游请求使用现有路由最终解析的真实目标名称。兼容判断复用这个结果，不重复套用映射，不依据公开名称的 `gpt` 前缀判断实际供应商能力。
- 明确映射到 DeepSeek 的账号，即使接在 OpenAI 兼容平台或第三方域名下，也进入本次 DeepSeek 适配范围；不要求目标地址必须是 `api.deepseek.com`。
- 不因一个账号映射到 DeepSeek 而修改同账号其他真实 GPT 模型的请求。分组可见性、显式路由、账号筛选和多目标冲突处理继续遵守已有规则。
- 请求模型、实际目标模型与上游返回模型的既有日志/用量归属保持区分，不把 DeepSeek 用量伪写为真实 GPT 上游用量。

### R2. 能力目录

- 目录缺失字段以映射后的真实模型补全；有效的目标模型能力快照优先于内置默认值。不得因公开名称是 GPT 而补入 GPT 的推理档位、速度档位、工具模式或上下文能力。
- 明确映射到 DeepSeek 的条目使用标准 Responses，`use_responses_lite=false`；不声明依赖 GPT 私有执行协议的 `code_mode_only`。
- 推理档位、输入模态、上下文窗口和工具能力取真实目标的已知能力。没有可信能力信息时使用现有保守回退，不凭别名扩大能力。
- 公开别名不变，目录补全结果不污染共享上游缓存或其他账号/分组的目录；ETag 根据最终返回内容计算，能力变化后不能继续用旧 ETag 返回未变更状态。
- 无需用户改客户端配置。允许 Codex 通过正常模型目录刷新获得更新；服务端不能依赖客户端立刻清空已有目录缓存才能适配后续核心请求。

### R3. 请求、工具与响应适配

- 根据实际目标模型对核心 Responses 请求做兼容处理，复用已有 namespace 展平、自定义工具转函数工具、工具搜索适配和响应恢复逻辑。
- 工具名称、参数、`call_id`、工具结果和响应事件在往返后保持对应关系；不把工具调用当普通文本，也不丢弃工具结果。
- 对携带旧 GPT 能力信息的核心请求，在已有适配器能够保持语义时转换为标准 Responses；不得把仅适用于 GPT 的 Lite 标记或工具模式直接转发给 DeepSeek。
- 推理选项依据真实 DeepSeek 目标处理。需要归一化时采用 DeepSeek 的兼容关系：`minimal→low`、`medium/xhigh→high`、`ultra→max`，`low/high/max` 保持；真实支持关闭思考时保留 `none` 的关闭语义。现有显式分组拒绝规则仍优先，不绕过管理员策略。
- 本次必须保持语义的客户端工具类型为现有适配器支持的 `function`、`custom`、`namespace` 与客户端 `tool_search`；函数调用输入和输出均属于核心契约。
- 对无法转换的其他专有协议或工具请求，使用现有 `invalid_request_error` 错误信封；HTTP 返回 400，WebSocket 使用现有错误事件，`param` 指向不兼容字段，`message` 说明实际目标与不支持的能力。不伪造成功或静默删除核心意图；此边界不算实现 GPT 私有功能。
- 真实 OpenAI 路由、其他模型和未命中 DeepSeek 映射的请求不受本次规则影响。

### R4. 流式传输和多轮续接

- HTTP/SSE 输出包含可供 Codex 识别的工具与结束事件；已有 WS → HTTP Bridge 路径继续向客户端提供原有 WebSocket 事件契约，上游按实际目标使用兼容请求。
- 复用已恢复的完整对话历史与工具映射，适配无状态上游。去掉不适用的 `previous_response_id` 时必须保留等价的历史输入，不能只删除关联标识而丢失上下文。
- 续请求省略工具定义时，在现有会话恢复范围内继续恢复此前工具映射；不同会话和账号之间不串用状态。
- 若请求只有不可恢复的引用或无法解释的核心历史内容，使用同一 `invalid_request_error` 信封，HTTP 返回 400、WebSocket 返回现有错误事件，`param` 指向 `previous_response_id` 或 `input`，提示需要完整历史；不发出已丢失历史的上游请求。不要求解释可忽略且不影响消息/工具历史的供应商私有附加信息。
- 不新增无限重试，不改变现有取消、断连和输出后故障转移边界；不覆盖当前工作区已有容量故障处理改动。
